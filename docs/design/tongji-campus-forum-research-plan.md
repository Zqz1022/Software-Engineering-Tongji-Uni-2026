## 二、项目章程与业务范围

### 2.1 业务目标与服务对象

项目服务对象为同济大学本科生、研究生及学生组织成员，覆盖课程组队、学习讨论、活动咨询及校园互助场景。项目通过 QQ 或微信登录建立本站账号与会话，通过板块和帖子组织公共信息，通过私聊承接进一步沟通，并通过 VIP 提供个性化展示服务。

| 目标编号 | 业务目标 | 可检查的结果 |
| --- | --- | --- |
| G-01 | 按主题组织校园信息 | 浏览帖子，按板块、校区和关键词查找内容 |
| G-02 | 提供便捷的第三方登录与普通交流入口 | QQ 或微信登录成功后直接获得发帖、评论和私聊能力 |
| G-03 | 衔接公开讨论与一对一交流 | 从帖子作者入口进入私聊，发送消息并查看历史 |
| G-04 | 提供可购买的会员个性化服务 | 支付宝或微信支付成功后开通 VIP，展示金色昵称和主页装扮 |
| G-05 | 建立社区治理和工程记录 | 管理操作可追溯，需求、设计、代码与测试通过 Issue、PR、CI 和 Release 留痕 |

### 2.2 四类用户与权限

系统采用普通用户、VIP 用户、版主和管理员四类业务角色。QQ 或微信首次有效登录自动创建普通账号，再次登录进入同一账号；用户登录后可直接浏览、搜索、发帖、评论及私聊。未登录仅为会话状态，不设置游客账号；本站业务页面要求登录。第三方登录用于账号认证，不校验学籍信息。

| 用户类型 | 身份条件 | 主要权限 |
| --- | --- | --- |
| 普通用户 | 已通过 QQ 或微信登录建立本站账号，当前会话有效 | 浏览、搜索、发帖、评论、管理本人内容、资料、私聊、拉黑、举报及购买 VIP |
| VIP 用户 | 普通用户完成充值，会员处于有效期内 | 普通用户全部功能，以及金色昵称、主页装扮 |
| 版主 | 普通账号获得指定板块管理授权 | 普通交流功能、授权板块的公开内容管理及举报处理 |
| 管理员 | 普通账号获得系统管理授权 | 普通交流功能及全站板块、角色、账号限制、举报、VIP 套餐和订单管理 |

登录会话、VIP 有效期和管理授权分别判定。第三方昵称、头像和登录结果不能直接授予 VIP 或管理权限；支付只更新会员权益，管理授权由本站控制。管理人员同时具备有效 VIP 时可以使用会员展示权益。

| 能力 | 普通用户 | VIP 用户 | 版主 | 管理员 |
| --- | --- | --- | --- | --- |
| 浏览帖子、搜索、发帖、评论和私聊 | 允许 | 允许 | 允许 | 允许 |
| 管理本人内容、资料、拉黑和举报 | 允许 | 允许 | 允许 | 允许 |
| 购买或续费 VIP | 允许 | 允许 | 允许 | - |
| 金色昵称和 VIP 主页装扮 | 无 | 会员有效期内允许 | 同时具备有效 VIP 时允许 | 同时具备有效 VIP 时允许 |
| 公开内容治理 | 无 | 无 | 限授权板块 | 全站管理 |
| 板块、角色与 VIP 套餐管理 | 无 | 无 | 无 | 允许 |

未登录或会话失效的请求由服务端拒绝并引导登录，退出不删除账号和历史。VIP 到期后保留普通交流能力，昵称与主页恢复普通显示；账号限制对所有角色生效。

私聊仅向会话参与者开放。管理员处理私聊举报时只能查看举报人选取且获授权处理的相关证据；版主管理授权板块的公开内容。

### 2.3 功能范围

本期范围包括 QQ 登录、微信登录、首次登录建号和会话管理、个人资料、板块与校区标签、帖子与评论、搜索、一对一文本私聊、消息历史与未读、拉黑与举报、VIP 套餐与充值、金色昵称、主页装扮及后台管理。

独立密码注册、跨渠道账号绑定或合并、群聊、音视频通话、文件私聊和推荐算法列入本期范围外。支付业务用于 VIP 购买和续费，支付订单记录购买人、套餐、渠道、金额、交易状态和会员权益发放结果。

## 三、外部集成与业务规则

### 3.1 QQ 与微信登录

用户在本站选择 QQ 或微信，由对应平台处理授权。本站服务端验证登录上下文和授权结果，再以“渠道、应用标识、渠道用户标识”定位本地账号。首次登录自动创建普通账号并建立会话；后续登录复用原账号，保留会员期限、内容和管理授权。微信登录与微信支付为独立集成，登录不代表支付或会员开通。

| 规则编号 | 登录规则 | 验收要点 |
| --- | --- | --- |
| AUTH-01 | QQ、微信两个登录入口提供相同的普通交流能力 | 任一渠道首次有效登录均自动创建普通账号，可直接发帖评论；不增加独立身份关联步骤 |
| AUTH-02 | 登录发起上下文绑定浏览器、渠道、应用、一次性 state 与有效期，由服务端验证授权码和平台身份 | 伪造、过期、跨渠道、跨浏览器和重放结果被拒绝，不信任客户端直接提供的账号标识 |
| AUTH-03 | 渠道身份与本站账号保持唯一映射 | 同一渠道与应用下重复或并发首次登录不重复建号；不同渠道的相同标识、昵称或头像不自动合并账号 |
| AUTH-04 | 本站不收集 QQ 或微信密码，仅保存业务所需身份映射并管理本站会话 | 第三方凭据仅由服务端处理并脱敏记录；登录不授予 VIP、版主或管理员权限 |
| AUTH-05 | 退出与会话过期撤销当前访问资格，账号和历史保留 | 失效会话不能发帖；重新有效登录仍进入原账号，受限账号不能借再次登录绕过限制 |

QQ 使用 QQ 互联授权登录，微信使用微信开放平台网站应用登录。应用资质、审核、回调地址和有效配置遵循对应平台要求；配置由运行环境管理，不将密钥写入仓库。跨渠道账号绑定或合并不属于本期范围。

### 3.2 支付宝与微信支付 VIP 充值

普通用户选择 VIP 套餐及支付渠道后，由服务端生成充值订单并调用支付宝或微信支付接口。订单金额和会员时长取自服务端套餐配置，并保存为订单快照。前端展示支付入口及订单状态，会员发放以服务端核验后的支付结果为依据。

| 环节 | 业务处理 | 验收要点 |
| --- | --- | --- |
| 选择套餐 | 展示 VIP 权益、价格和有效时长 | 用户可在支付前查看购买内容 |
| 创建订单 | 校验本站会话和账号状态，保存套餐、购买人、金额、币种及渠道 | 客户端修改价格或账号参数不能改变服务端定价和购买人 |
| 调起支付 | 根据选定渠道调用支付宝或微信支付接口 | 每个订单具有唯一编号，并绑定一个支付渠道 |
| 确认支付 | 验证平台签名，核对商户或应用标识、订单、金额、币种及交易状态 | 经核验的成功支付进入会员发放流程，页面跳转结果仅用于展示 |
| 发放权益 | 保存支付流水，更新订单和会员有效期 | 同一订单只发放一次权益，重复回调返回一致结果 |
| 查询补偿 | 对支付结果通知延迟的订单主动查询支付平台 | 查询确认成功后进入同一发放流程，重试能够恢复中断处理 |
| 未支付关闭 | 对取消或超时订单按支付平台结果更新状态 | 未确认支付成功的订单保持原会员权益 |

订单状态和会员权益采用一致的事务处理，确保支付成功记录与会员发放结果对应。并发处理同一订单时仅发放一次；不同续费订单分别生效，并累加各自购买的会员时长。关闭订单与支付确认发生竞态时，通过平台查单核对结果。

### 3.3 VIP 权益与生命周期

| 规则编号 | 会员规则 | 验收要点 |
| --- | --- | --- |
| VIP-01 | 普通用户支付成功后开通 VIP | 从成功发放权益的时间开始计算套餐有效期 |
| VIP-02 | VIP 用户可以使用金色昵称 | 帖子、评论和个人主页中的昵称采用统一的 VIP 金色样式 |
| VIP-03 | VIP 用户可以设置主页装扮 | 从平台提供的装扮中选择，保存后访问个人主页可见对应效果 |
| VIP-04 | 有效期内续费延长当前会员期限 | 从现有到期时间增加购买时长；已到期时从本次权益发放时间重新计算 |
| VIP-05 | 到期后恢复普通展示 | 金色昵称和专属主页装扮停用，普通用户交流能力保留 |
| VIP-06 | 会员权益由服务端账号状态决定 | 修改客户端会员字段、伪造回调或重复提交支付结果不能获取额外权益 |

## 五、用户故事与验收标准

本节包含 26 条功能故事和 2 条非功能故事，共 28 条。每条故事具有 Given / When / Then 验收条件，用于需求规约、设计和测试追溯。

| 编号 | 用户故事 | Given / When / Then 验收标准 | 依据 |
| --- | --- | --- | --- |
| US-01 | 作为使用者，我希望使用 QQ 登录，以便进入校园论坛并参与交流 | Given 已选择 QQ 且登录请求上下文有效；When 完成 QQ 授权并由服务端核验身份；Then 首次登录自动创建普通账号，后续登录进入同一账号，立即具备发帖评论能力，取消或伪造授权不能建立本站会话 | P-04、S-06、AUTH-01、AUTH-02、AUTH-03 |
| US-02 | 作为普通用户，我希望维护昵称与校区资料，以便展示交流身份 | Given 用户已登录；When 保存本人昵称和校区；Then 刷新后显示新资料，修改资料不能改变第三方身份映射、会员期限或管理权限 | S-02、S-06 |
| US-03 | 作为普通用户，我希望浏览板块帖子列表，以便了解校园话题 | Given 用户已登录且账号正常；When 选择课程组队、学习交流、校园生活或活动信息板块；Then 显示对应公开帖子列表，并提供符合当前权限的发帖入口 | S-01、S-02、P-04 |
| US-04 | 作为普通用户，我希望发布带校区标签的帖子，以便说明求助或组队内容 | Given 用户已登录且账号状态正常；When 提交有效标题、正文、板块和校区标签；Then 创建帖子并显示作者，空内容和未登录提交均被服务端拒绝 | S-01、S-02、S-06 |
| US-05 | 作为普通用户，我希望查看帖子详情，以便了解交流内容 | Given 用户已登录且帖子公开可见；When 打开详情；Then 显示标题、正文、作者、板块、校区和公开评论，评论与私聊操作按账号状态及对象权限执行 | S-02、P-04 |
| US-06 | 作为普通用户，我希望发表评论，以便参与公开讨论 | Given 用户已登录且帖子允许评论；When 提交有效评论；Then 评论显示在该帖下并保留作者和时间，空评论及未登录评论请求被拒绝 | S-01、S-03、S-06 |

## 六、技术风险与质量要求

| 编号 | 风险及影响 | 处理方案 | 验证标准 |
| --- | --- | --- | --- |
| R-01 | 消息重试造成丢失或重复 | 保存成功后确认发送，按客户端请求标识去重，重连同步历史 | US-18 重复请求在数据库与历史中仅形成一条消息 |
| R-02 | 身份与角色校验不足导致越权 | 服务端统一检查本站会话、账号限制、会员期限、管理范围及会话成员关系 | US-19 越权场景全部被拒绝 |

测试覆盖 QQ／微信登录、未登录与会话失效限制、普通交流、VIP 支付及展示、管理权限和消息可靠性。支付测试包括金额篡改、伪造通知、重复通知、并发续费、回调延迟与处理失败恢复。验证结果按用户故事编号记录。

## 七、开发过程与交付方案

### 7.1 增量开发

项目采用增量模型，每轮执行计划、构造、测试、评审和回顾。第三方登录和本站会话构成访问基础，公开讨论和私聊形成交流流程，会员充值和治理在此基础上完成扩展。该划分便于分别验证登录、消息和支付风险。

| 增量 | 交付范围 | 验收演示 |
| --- | --- | --- |
| v0.1 | QQ／微信登录、首次登录建号、帖子评论和搜索 | 任一渠道首次登录即能发布组队帖与评论，再次登录进入原账号 |
| v0.2 | 私聊、消息持久化、历史、未读、重试去重和拉黑 | 已登录账号从帖子进入私聊，验证历史读取及重复请求去重 |
| v0.3 | 支付宝与微信支付、VIP 金色昵称和主页装扮、续费到期、社区治理及部署验证 | 支付后开通会员并使用装扮，演示到期恢复、权限控制和性能结果 |

三轮增量分别保留计划、测试、评审与回顾，形成至少三个可交付增量和完整迭代记录。
