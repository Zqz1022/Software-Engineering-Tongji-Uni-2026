## 2. 张启政：账号、社区治理与安全

组内交付闭环：第三方登录建立普通账号 → 编辑本人资料 → 提交举报 → 授权人员处置 → 审计可追溯。集中维护治理规则，避免论坛、私聊和会员各自实现一套管理权限。

| 故事 | 建议 Milestone | 验收要点 |
| --- | --- | --- |
| [US-01 QQ 登录](../requirements/user-stories.md#us-01) | v0.1 | 有效 QQ 授权首次创建普通账号，重复登录定位同一账号并能发帖评论；取消、伪造或无效上下文不能建立会话；身份映射使用服务端核验的渠道、应用及用户标识。 |
| [US-21 微信登录](../requirements/user-stories.md#us-21) | v0.1 | 微信登录具备同样的首次建号、重复登录与失败拒绝行为；QQ 与微信分别按渠道身份映射，不按同名或相同头像自动合并账号。 |
| [US-02 个人资料](../requirements/user-stories.md#us-02) | v0.1 | 本人昵称、校区保存后刷新仍生效；不能改他人资料；夹带第三方身份、会员期限或管理权限字段不能改变相应数据。 |
| [US-15 提交举报](../requirements/user-stories.md#us-15) | v0.3 | 对可访问的帖子、评论或本人收到的选定私聊消息提交原因，生成举报编号及状态；私聊证据只包含所选相关消息，伪造消息编号或提交无权访问的对象被拒绝。 |
| [US-16 版主处理举报](../requirements/user-stories.md#us-16) | v0.3 | 版主可处理授权板块公开内容举报，处置理由、结果和操作记录保存；需要隐藏的内容在普通列表、搜索和详情中均不可见；跨板块操作被拒绝，版主不能借此读取私聊证据。 |
| [US-17 平台管理](../requirements/user-stories.md#us-17) | v0.3 | 管理员可管理板块、版主范围、账号限制、举报分派、VIP 套餐及 SRS 要求的订单查询；保存操作人、对象、时间和理由；套餐变更不改历史订单快照；普通用户及无管理授权的 VIP 被拒绝，私聊证据访问受举报处理授权限制。 |
| [US-19 安全与权限](../requirements/user-stories.md#us-19) | v0.3，v0.1 起持续验证 | 未登录或会话过期不能访问业务；非参与者不能读会话；不能读他人订单、修改他人内容、跨板块管理或查看未授权举报证据；伪造身份、角色或会员字段不提升权限；拒绝响应不泄露私聊正文。 |

US-19 由张启政维护全系统权限测试矩阵和验收报告；各功能负责人实现本模块校验并提交正反例测试。不能等到最后一轮才补权限检查，也不能将其他组的全部安全测试转交组长。

US-17 建议拆成关联实现任务：张启政负责管理入口、授权、账号限制、举报分派与审计整合；刘笑云负责 forum 的板块管理及内容治理服务；李灏文负责 membership 的套餐管理和授权订单查询服务。父故事验收覆盖全部任务后再关闭。

## 3. 刘笑云：论坛

组内交付闭环：广场选板块 → 发帖 → 列表与详情可见 → 评论 → 作者修改或删除 → 搜索与校区筛选。

| 故事 | 建议 Milestone | 验收要点 |
| --- | --- | --- |
| [US-03 板块帖子列表](../requirements/user-stories.md#us-03) | v0.1 | 正常登录账号可切换四个校园板块，列表只显示对应板块可见帖子，并显示符合权限的发帖入口；未登录请求被拒绝。 |
| [US-04 发布帖子](../requirements/user-stories.md#us-04) | v0.1 | 有效标题、正文、板块及校区标签可保存，作者来自当前会话，刷新列表和详情可见；空内容、未登录或受限账号提交被服务端拒绝。 |
| [US-05 帖子详情](../requirements/user-stories.md#us-05) | v0.1 | 显示标题、正文、作者、板块、校区及公开评论；删除或隐藏内容不可普通访问；评论与私聊入口遵守权限，私聊功能的端到端联调关联 US-10 在 v0.2 验证。 |
| [US-06 发表评论](../requirements/user-stories.md#us-06) | v0.1 | 允许评论的帖子下保存有效评论，刷新仍显示作者及时间；空评论、未登录提交及不允许评论的对象被拒绝。 |
| [US-07 编辑本人帖子](../requirements/user-stories.md#us-07) | v0.1 | 作者修改后刷新生效；另一个普通用户直接请求修改该帖也被拒绝，不能只靠隐藏编辑按钮。 |
| [US-08 删除本人内容](../requirements/user-stories.md#us-08) | v0.1 | 作者确认后可删除本人帖子或评论，普通列表、搜索、详情相应隐藏；其他普通用户删除失败；管理处置走独立授权接口。 |
| [US-09 搜索与校区筛选](../requirements/user-stories.md#us-09) | v0.1 | 关键词匹配标题或正文，并与所选校区条件同时生效；无结果有提示；结果不包含删除、隐藏或无权访问的帖子。 |

跨组协作：在帖子／评论接入统一举报组件；在作者入口传递用户 ID 发起私聊；在作者展示处使用统一会员展示组件。刘笑云负责这些入口在论坛中的接入及联调，举报、私聊、支付规则分别由对应模块实现。

## 4. 周禹佟：私聊与消息质量

组内交付闭环：选择对方建立唯一会话 → 收发消息 → 查看历史与未读 → 离线重连与重试 → 拉黑阻止新消息。

| 故事 | 建议 Milestone | 验收要点 |
| --- | --- | --- |
| [US-10 发起私聊](../requirements/user-stories.md#us-10) | v0.2 | 从作者入口进入双方唯一会话，重复或并发发起不产生重复会话；对方离线仍可建立；未登录、自聊、受限账号及存在拉黑关系的请求被拒绝。 |
| [US-11 会话列表与历史](../requirements/user-stories.md#us-11) | v0.2 | 列表只包含本人会话，消息保存后重新登录仍可读取；第三个账号篡改会话编号不能读取列表外的历史。 |
| [US-12 文本消息](../requirements/user-stories.md#us-12) | v0.2 | 仅合法参与者可发送 1—2000 字符非空文本；保存成功后确认，在线接收者可见，离线者从历史补齐；空白、超长、受限或拉黑状态被拒绝；保存失败显示失败。 |
| [US-13 未读数](../requirements/user-stories.md#us-13) | v0.2 | 收到消息后未读数正确增加；读取至指定消息只清除该范围内未读；并发到达的新消息仍计数，不能清除他人会话未读。 |
| [US-14 拉黑与解除](../requirements/user-stories.md#us-14) | v0.2 | 拉黑后服务端拒绝双方新消息，原参与者仍能读历史；解除后恢复合法发送；HTTP 与实时通道执行相同规则。 |
| [US-18 断线重试去重](../requirements/user-stories.md#us-18) | v0.2 | 相同客户端请求标识重试或并发提交返回同一已保存消息，数据库及历史只出现一次；原请求未保存时可重新提交成功。 |
| [US-20 消息性能](../requirements/user-stories.md#us-20) | v0.2 | 同一测试网络下 20 个已登录模拟用户，合计每秒 5 条消息持续 5 分钟；发送至接收端显示的 P95 延迟 ≤ 1 秒，消息均保存一次且接收端可见；报告记录环境、原始统计、失败和丢失／重复核对结果。 |

US-20 必须覆盖接收端收到并显示消息的测量点，不能以 HTTP 响应耗时代替。正常负载约 1500 次发送，报告记录实际发送数量及重试请求，区分业务消息数和网络请求数。v0.3 集成完成后运行受影响的回归场景。

周禹佟另外提供私聊举报入口及受控证据读取能力：核验举报者是所选消息的接收者，只向治理模块返回所选相关证据，不开放任意完整会话查询。该协作工作关联 US-15，计划在 v0.3 完成联调。

| 故事 | 建议 Milestone | 验收要点 |

| [US-23 支付宝充值](../requirements/user-stories.md#us-23) | v0.3 | 仅绑定支付宝且可支付的本人订单进入支付；服务端核验成功后更新订单并发放一次权益；取消不改变原权益，前端成功提示不能自行授予 VIP。 |

| [US-25 金色昵称与装扮](../requirements/user-stories.md#us-25) | v0.3 | 有效 VIP 在帖子、评论和个人主页统一显示金色昵称，可保存并展示平台提供的主页装扮；普通账号直接调用专属设置接口被拒绝。交付可访问的个人主页展示，不能只完成充值页预览。 |
| [US-26 续费与到期](../requirements/user-stories.md#us-26) | v0.3 | 到期时间按 max（当前到期时间，发放时间）累加购买时长；并发不同成功订单分别累加；到期即停用金名和专属装扮，普通交流及独立管理授权保留。 |
| [US-27 订单与会员期限](../requirements/user-stories.md#us-27) | v0.3 | 本人可查询渠道、金额、支付状态、权益状态及期限；通知延迟通过服务端查单核对；篡改订单编号不能读取他人订单。 |
| [US-28 支付幂等与恢复](../requirements/user-stories.md#us-28) | v0.3 | 重复通知、通知与查单并发、中途失败后重试，均只发放一次权益并可恢复一致状态；校验签名或可信响应、商户／应用、订单、金额、币种和成功状态；伪造或不匹配结果被拒绝。 |

US-25 的会员展示组件与主页装扮由李灏文负责；刘笑云接入帖子和评论，张启政提供资料查询及主页路由协作。US-17 的套餐管理和订单查询由 membership 提供服务，套餐调价或下架不改写历史订单。

QQ／微信登录、支付宝／微信支付在开发开始时分别核验接入条件、回调及可用测试能力。dev/test 模拟适配器用于并行开发和故障测试；模拟成功不能作为真实外部接入完成的证据，接入条件变化通过需求 Issue 处理。

## 6. 跨组接口与并行顺序

### 6.1 先约定接口，再分别实现

下表是需要在开发前落实到契约中的能力边界，不表示当前代码已存在这些业务接口。跨模块通过服务调用，不直接读写其他模块的业务表。

| 能力提供者 | 提供内容 | 使用者与边界 |
| --- | --- | --- |
| 张启政：auth／user | 当前用户、账号状态、基础资料、管理角色及板块授权范围 | 三个业务模块调用统一能力；不得信任客户端传入的身份和角色 |
| 刘笑云：forum | 板块管理、举报对象可访问性、内容所属板块、隐藏内容 | moderation 发起已授权的治理操作；forum 保证列表、搜索、详情一致隐藏 |
| 周禹佟：chat | 按目标用户打开会话的入口、私聊举报所选证据校验 | forum 只传目标用户；moderation 只获得举报者有权提交的指定证据 |
| 李灏文：membership | 权益有效性、到期时间、金名／装扮展示数据、套餐管理及授权订单查询 | forum／user 展示权益；moderation 调用管理能力；不能由前端声明 VIP 有效 |
| 张启政：moderation | 举报提交组件与 API、举报状态、处理权限和审计 | forum／chat 负责接入入口；三方共同验证对象和证据权限，不自行复制举报处理流程 |

共同修改 `contracts/openapi.yaml`、前端路由、公共布局或 Flyway 迁移时，在对应 Issue 明确修改人及合并顺序。业务表由所在模块负责人维护；新增迁移版本由组长协调避免重号，已执行迁移不覆写。

### 6.2 实现依赖与验收依赖

| 分组 | 建议组内实现顺序 | 最终跨组验收依赖 |
| --- | --- | --- |
| 账号与治理 | US-01／21 → US-02；US-15 → US-16／17；US-19 持续补充 | 登录后发帖评论需论坛联调；举报需论坛对象及私聊证据；管理需板块和套餐服务 |
| 论坛 | US-03／04／05 → US-06 → US-07／08／09 | auth／user；之后分别与 US-10、US-15、US-25 联调私聊、举报、金名入口 |
| 私聊 | US-10／11 → US-12（同时设计 US-18）→ US-13／14 → US-20 | auth／user；最终从真实帖子作者入口发起；US-15 联调证据提交 |
| VIP | US-22 → US-23／24（同时设计 US-28）→ US-27 → US-26／25 | auth／user；帖子、评论、个人主页展示；US-17 管理套餐与订单 |

四人可以从框架的开发会话开始并行，不必等待 QQ／微信接入完成。先固定契约和准备测试数据，再替换对应模块的开发中页面；测试替身只用于 dev/test。只有满足原故事全部验收条件及真实跨模块联调后，才能关闭相应故事。

增量沿用 v0.1（登录与论坛）、v0.2（可靠私聊）、v0.3（会员与治理）。Milestone 表示验收归属，不要求私聊或支付负责人等上一增量发布后才开始开发。若 US-05 中涉及私聊的原验收条件在 v0.1 尚不能完整验证，该故事保留开放并记录已完成切片，在 v0.2 联调完成后关闭，不能仅凭界面入口关闭。

## 7. 手动建立 Issue 与关闭条件

使用仓库的“用户故事”Issue 模板，每个 US 建一条主 Issue。依次执行：

1. 搜索标题中的 US 编号，确认是否已有同一故事。
2. 标题采用 `[US-04] 发布带校区标签的帖子` 等格式；复制原清单的故事原文及 Given／When／Then。
3. 设置表中的一名 Assignee 和 Milestone；组员姓名对应实际 GitHub 账号后选择，不把姓名当作账号名。
4. 在“任务、依赖与协作者”中填写实现范围、跨组协作者及上述接口依赖；依赖 Issue 建立后填写实际 `#编号`。
5. 验收证据由负责人在交付时填写关联 PR、CI、测试报告和演示记录，不提前标记通过。

例如 US-04 的任务栏可填写：

```text
主要负责人：刘笑云（同时在 Assignee 中选择其 GitHub 账号）
Milestone：v0.1
交付：发帖页面、创建帖子接口、数据库迁移、列表／详情联调、验收测试。
依赖：auth／user 提供有效会话与账号状态；板块与校区数据；
      US-03／US-05 用于验证发布后的列表与详情。
```
