# SRS 变更记录

本文件记录需求规约的版本变化。SRS 使用 `srs-` 前缀的发布标签，与软件增量 `v0.1`、`v0.2`、`v0.3` 分别管理。基线后的变更通过 Issue 提出、PR 评审与合并，并在此记录受影响的需求编号、验收条件及处理结果。

## 1.0 — 2026-11-27

发布标识：`srs-v1.0`。从 0.2 课前评审稿形成第 3 次课后的需求基线，供分析建模、设计与验收引用。

| 变化 | 涉及范围 | 对需求与验收的影响 |
| --- | --- | --- |
| 明确三块结构及阅读索引 | SRS 第 1、4、5、8 节 | 功能需求包含用例编号、行为描述与 Given / When / Then；非功能需求包含指标和场景；约束条件单独列示并给出核对方式。 |
| 整理 8 项显式约束 | CON-01 至 CON-08 | 汇总既定范围、第三方接入、浏览器与部署、已选技术栈、凭据与隐私、订单与时间、课程交付及基线管理边界。技术约束与已确定的 Vue 3／Spring Boot／MySQL 框架保持一致。 |
| 澄清拉黑解除条件 | FR-14、UC-14；依据 BR-05 | 仅在双方全部有效拉黑关系解除并满足账号及会话权限条件后恢复发送。单方解除不覆盖另一方仍有效的拉黑；保留双方历史读取规则。 |
| 固定配套材料与引用 | FR-01 至 FR-26、NFR-01 至 NFR-03、UC-01 至 UC-26、US-01 至 US-28 | 保留全部原编号、功能范围、三项质量要求及原有质量指标；用户故事继续在独立清单维护，用例与场景说明同步标识为 1.0 配套版。 |
| 建立文档发布基线 | SRS 元数据、模型索引、Release 说明及本记录 | 使用 srs-v1.0 标签固定提交，随 Release 提供需求文档、图源、SVG、来源报告及变更记录。需求文档版本不表示软件功能已完成验收。 |

业务范围沿用 QQ／微信登录、普通／VIP／版主／管理员四类业务角色、一对一文本私聊及支付宝／微信支付。非功能指标继续为权限越权场景全部拒绝，以及 20 个在线模拟用户、合计每秒 5 条消息、持续 5 分钟时端到端显示 P95 ≤ 1 秒，正常负载消息无丢失、无重复。

本版人工评审与合并依据保存在对应 PR；Release 的标签和提交标识用于定位本版文件及历史。

## 0.2 — 2026-11-24

- 根据项目组的登录方案变更，采用 QQ／微信授权登录。首次有效登录自动创建普通账号，重复登录定位原账号。
- 取消同济身份认证及游客账号，统一普通、VIP、版主、管理员四类业务角色。未登录仅表示会话状态，业务页面要求登录。
- 同步登录用例、活动图、用户故事引用及权限边界；微信登录与微信支付分别处理。

## 0.1 — 2026-11-23

- 首次汇编 26 项功能需求与 3 项非功能需求，形成第 3 次课课前评审稿。
- 配套完整用例模型、三个细化场景及活动图、外部接口业务契约和验收条件。
