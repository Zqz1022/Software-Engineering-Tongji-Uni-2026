| --- | --- | --- | --- |
| <a id="us-10"></a>US-10 | 作为普通用户，我希望从作者入口发起私聊，以便进一步交流 | Given 发起者已登录、双方账号正常且不存在拉黑关系；When 点击作者私聊入口；Then 打开双方唯一会话，重复点击返回同一会话，未登录及本人自聊请求被拒绝，接收者离线不影响合法会话建立 | P-01、S-01、S-03、P-04 |
| <a id="us-11"></a>US-11 | 作为会话参与者，我希望查看会话列表和历史，以便继续交流 | Given 用户已登录且参与相应会话；When 打开列表和会话；Then 显示本人会话及已保存消息，再次登录仍可读取，其他用户不能访问 | S-01 |
| <a id="us-12"></a>US-12 | 作为会话参与者，我希望收发文本消息，以便一对一沟通 | Given 发送者会话有效、双方账号正常、具备会话权限且未拉黑；When 发送 1—2000 字符的非空文本；Then 服务端保存后确认成功，在线接收者可见消息，离线接收者可从历史补齐，保存失败时显示失败 | P-01、S-01、P-02 |
| <a id="us-13"></a>US-13 | 作为普通用户，我希望看到未读数量，以便发现新的联系 | Given 用户收到未读消息；When 查看会话列表；Then 显示未读数，进入会话并确认读取至指定消息后，已读范围内消息不再计数，新消息继续计数 | S-01、S-03 |
| <a id="us-14"></a>US-14 | 作为普通用户，我希望拉黑其他账号，以便停止接收其新消息 | Given 双方存在联系；When 拉黑对方；Then 服务端拒绝双方后续发送请求，历史仍可由原参与者查看，解除后恢复发送权限 | S-04 |
| <a id="us-18"></a>US-18 | 作为消息发送者，我希望断线重试后消息保持一致，以便确认发送结果 | Given 消息带固定客户端请求标识；When 网络恢复后用同一标识重试；Then 返回同一已保存消息，历史只出现一次，未成功保存的请求可再次提交 | S-01 |

## 5. VIP 与支付

| 编号 | 用户故事 | Given / When / Then 验收标准 | 依据 |
| --- | --- | --- | --- |
| <a id="us-22"></a>US-22 | 作为普通用户，我希望选择 VIP 套餐和支付渠道，以便购买会员服务 | Given 用户已登录且账号正常；When 选择在售套餐及支付宝或微信支付；Then 服务端创建属于本人的订单并保存套餐价格和时长快照，未登录请求及客户端价格篡改不能生成有效充值订单 | P-04、S-07 |
| <a id="us-23"></a>US-23 | 作为普通用户，我希望使用支付宝完成 VIP 充值，以便获得会员权益 | Given 本人订单绑定支付宝渠道且可支付；When 完成支付宝支付并由服务端核验成功；Then 订单更新为支付成功且会员权益发放一次，取消支付时保留原权益 | P-05、S-07、VIP-01 |
| <a id="us-24"></a>US-24 | 作为普通用户，我希望使用微信支付完成 VIP 充值，以便获得会员权益 | Given 本人订单绑定微信支付渠道且可支付；When 完成微信支付并由服务端验签、解密及业务校验成功；Then 订单更新为支付成功且会员权益发放一次，超时未支付时保留原权益 | P-06、S-07、VIP-01 |
| <a id="us-25"></a>US-25 | 作为 VIP 用户，我希望显示金色昵称并设置主页装扮，以便表达个人风格 | Given 会员处于有效期内；When 查看帖子、评论和个人主页，或保存平台提供的主页装扮；Then 昵称统一显示为 VIP 金色，主页呈现所选装扮，普通用户直接请求专属装扮设置被拒绝 | P-04、S-08、VIP-02、VIP-03 |
| <a id="us-26"></a>US-26 | 作为 VIP 用户，我希望续费与到期规则明确，以便持续使用会员权益 | Given 账号已有会员期限；When 新续费订单支付成功；Then 从现有到期时间与发放时间的较晚者累加购买时长，并发的不同成功订单分别累加；到期后金色昵称和专属装扮停用，普通交流及独立管理权限保留 | S-08、VIP-04、VIP-05 |
| <a id="us-27"></a>US-27 | 作为充值用户，我希望查看自己的订单和会员期限，以便核对购买结果 | Given 用户拥有充值订单；When 查看订单详情或刷新支付结果；Then 显示本人订单的渠道、金额、支付及权益状态，通知延迟时服务端通过查单核对，不能通过修改订单编号读取他人订单 | S-07、P-05、P-06 |
| <a id="us-28"></a>US-28 | 作为充值用户，我希望支付通知可重复处理且结果一致，以便可靠获得会员权益 | Given 平台发送支付通知或服务端查单确认结果；When 同一订单被重复或并发处理，或一次处理在中途失败后重试；Then 通过验签及商户、订单、金额、币种核对后仅发放一次权益，失败重试恢复一致状态，伪造或不匹配结果被拒绝 | P-05、P-06、S-07、VIP-06 |
